# Aceptación de software

Alcance: aceptación funcional de una versión candidata. Entrada: RFS, guion QA, resultados reales, versión/entorno y responsable requirente autorizado.

Consultar [proceso institucional](../../standards/institutional-process.md), [baseline F4](../../knowledge/institutional-forms.json), [guion F3](../../templates/forms/03-qa-plan.md) y [aceptación F4](../../templates/forms/04-acceptance.md).

1. Identificar aplicativo, módulo, códigos, resumen, URL de prueba y liberación. Vincular evidencia a la misma versión candidata.
2. Completar matriz Historia de usuario / Criterio de aceptación / Resultado / Comportamiento esperado / Aprobación / Observación con resultados sustentados. Dejar decisión pendiente si solo hay pruebas técnicas.
3. Revisar cumplimiento global Si/No y defectos pendientes con el responsable autorizado. Adjuntar evidencia de decisión real, declaración de pruebas y solicitud de liberación.
4. Entregar F4 y expediente trazable con observaciones, pendientes y firmas confirmadas cuando existan.

Conservar numeración 3 duplicada. El nombre del archivo dice Requirente, pero la instancia fuente contiene cargos DTI: identificar explícitamente la representación del requirente sin inferirla. No reutilizar nombres, cargos, códigos, marcas x ni Validado/Resuelto del caso fuente. La declaración impresa no equivale a aceptación emitida ni autorización productiva.
