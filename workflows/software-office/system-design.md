# Diseño de sistemas

## Activación y entrada

Solicitud de arquitectura con objetivos de negocio, flujos, restricciones y datos disponibles.

## Etapas

1. system-design: recopilar requisitos, distinguir supuestos y presentar arquitectura, alternativas y fallos relevantes.
2. professional-writing: cuando se solicite un documento, organizar la propuesta para la audiencia preservando decisiones y supuestos.
3. technical-presentation: cuando se solicite exposición técnica, adaptar narrativa y diagramas; puede usar presentation para el entregable.

## Salida

Propuesta con requisitos confirmados, supuestos, componentes, interfaces, alternativas y decisiones pendientes. Documento o presentación únicamente si se solicita.
No referenciar skills inexistentes como requirements-analysis o diagram-generation.
Detener decisiones de implementación dependientes de un requisito crítico desconocido; una propuesta preliminar puede entregarse con sus supuestos explícitos.
